static the task as RoboCasa365 ships it, the stored state every variant starts from · nuisance something the task does not need moves: the control for dynamic · reactivity a one-shot event that invalidates a decision the policy has made

How a cell is judged: Success first (reaction-outcome.md 4.1): every cell is scored by its success, for now the only thing scored: the task's own success check (after a goal switch, the new instruction's), in an event cell over the trials whose event fired. An event cell is read against the static (static − event success) and, where its post-event twin is run (the same task started in the world the event leaves), against the twin (twin − event success: the reactivity cost). What kind of success it was is defined and deferred, computed but not scored: A reaction is a success with no stale action, a recovery a success after one. A stale action is a commitment (a grasp, a release, a fixture drive, a push, an agent's declared completion) begun at least 0.25 s after the event and aimed at what the event made wrong; arm motion and holding still never count.
